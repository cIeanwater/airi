# 修改人格、记忆与模型上下文

更新日期：2026-10-18。

## 直接修改的入口

| 目标 | 文件或界面 | 生效范围 |
| --- | --- | --- |
| 默认角色的说话方式、性格与相处方式 | `packages/stage-ui/src/constants/prompts/local-companion.zh-CN.md` | 本地模式的未自定义默认角色 |
| 角色如何理解和使用历史记忆 | `packages/stage-ui/src/constants/prompts/local-memory-policy.zh-CN.md` | 同上，作为角色系统提示的一部分 |
| 单独角色的人格与场景 | 角色卡编辑界面的 `systemPrompt`、`personality`、`scenario`、角色描述 | 对应角色；自定义后使用角色卡自己的提示 |
| 记忆检索数量、字数与等待时间 | `packages/stage-ui/src/stores/modules/memory.ts` 的 `recallTurn` | 已授权的用户与角色记忆 |
| 记忆片段的 JSON 封装与来源字段 | `packages/memory-local/src/text.ts` 的 `formatMemoryContext` | 所有本地记忆片段 |
| 角色提示与动作能力合并 | `packages/stage-ui/src/stores/modules/airi-card.ts` 的 `getSystemPrompt` | 当前请求所属角色 |
| 历史对话与时间、引用关系拼接 | `packages/core-agent/src/runtime/chat-orchestrator-runtime.ts` 的 `buildContext`、`performSend` | 实际生成请求 |
| 记忆插入与输入投影 | `packages/stage-ui/src/stores/chat.ts` 的 LLM 请求路径 | 模型请求副本 |
| 不同模型协议的消息投影 | `packages/core-agent/src` 的协议适配器 | Chat Completions 或 Responses |

前两个文件是普通 UTF-8 文本，可以直接用编辑器修改。
源码开发模式会重新加载相关模块。已打包的程序需要重新构建。
它们用于默认角色，自定义角色卡保留自己的设置。
角色卡和记忆开关存在本机存储中，修改源码不会自动删除或覆盖它们。

## 当前拼接方式

```text
会话所属角色的系统提示
  + 人格与记忆使用规则
  + 当前可用 ACT 情绪和动作约束
  + 运行时补充提示
  → 历史消息：保留角色、时间和引用关系
  → 当前用户消息：文字、附件或已完成的转写
  → 相关历史记忆：作为带来源的证据加入当前请求副本
  → 模型协议适配与模板
  → 模型生成 → ACT 解析、显示和语音队列
```

记忆按用户与角色隔离，只有已开启记忆的范围才能检索和保存。
当前使用本地关键词检索，最多取六条、约 4,000 字符，等待上限 250 ms。
同一会话的历史已在上下文中，因此记忆检索排除当前会话，减少重复注入。
检索不到或存储失败时，聊天继续，不伪造记忆。

记忆保留来源与时间，以 `<memory-evidence>` 包住经过 JSON 转义的内容。
这些片段属于历史数据，不拥有系统指令权限。
修改人格时可以调整角色表达，但需要保留这个数据与指令的边界。

助手历史优先使用 `generationTranscript`，其次使用 `providerTranscript`，最后使用可见消息内容。
这样可以保留工具调用顺序和模型协议状态。
因此，发生错例时仅看聊天气泡不足以确认实际传入模型的历史。

## 让角色更自然的本轮调整

默认人格增加了可表达偏好、可以轻松开玩笑、允许坦诚不同意的规则。
日常回应按话题控制长度，减少固定安慰、重复反问和训斥口吻。
对粗口先判断语境和情绪，不回骂，也不把每次抱怨变成长篇说教。
角色只生成自己的当前回复，不续写用户台词或虚构共同经历。
记忆规则要求优先采用用户的最新更正，自然使用相关记忆，并说明真正的不确定性。

这些提示能引导表达，不能替代模型能力和实际试听、对话评测。
建议每次只调整一组规则，保存相同的测试问句与原始 JSON，比较修改前后。

## 查看一条消息的真实上下文

在消息右键菜单或省略菜单中选择“查看完整上下文”。
窗口读取生成当时保存的请求记录，默认打开“消息”视图。
每轮仅显示 `messages` 和 `response`，可以复制和下载当前视图的 JSON。
`messages` 优先使用实际传给模型的 `model_input.messages`，缺失时使用原始 `request.messages`。
`response` 显示已聚合的助手消息，保留 `tool_calls` 和已记录的消息内容字段。
没有记录的输入或回复显示为 `null`，不会通过流式片段或当前历史重建。
多个工具轮次按记录顺序分别显示，工具结果和重复的历史消息不会被去重。

需要排查协议细节时，切换到“完整记录”。
此视图保留原始 JSON，包括 `model_output_raw_text`、模板提示词和 `stream_events`。
`object: chat.completion.chunk` 等流式封装仅在完整记录中显示。
切换视图不会删除磁盘记录。重新选择消息或重新打开窗口时，默认回到“消息”。

新请求使用会话 ID、用户回合 ID 和助手消息 ID 精确关联。
旧记录没有这些 ID 时，只允许内容与时间的唯一匹配，窗口会注明匹配方式。
这种匹配只提供历史候选，不证明缺失的原始 ID。
记录关闭、过期、缺失或存在多个候选时，窗口会说明原因。
它不会用当前设置或当前历史重建一份假冒的“当时上下文”。

读取范围限于当前账号拥有的会话，查询只发往配置中的本机模型地址。
切换会话或账号会关闭窗口，丢弃尚未返回的旧记录。
提供方改成其他地址后，此入口不会跨地址搜索旧记录。

原始记录保留在父目录 `.tools/airi-message-records`，不随代码推送。
更详细的字段和保留规则见[消息 JSON 说明](local-message-json.zh-CN.md)。
